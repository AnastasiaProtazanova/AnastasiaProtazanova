<h3>💡 1. Дипломный проект: «Управление ИТ-фирмой» (часть 1)</h3>

**Что реализовано**

| Блок | Объекты | Что умеет |
|---|---|---|
| **Справочники** | Контрагенты, Сотрудники, Номенклатура, НоменклатурныеГруппы | Хранение и редактирование данных |
| **Документы** | Поступление/Реализация товаров и услуг, Установка цен/скидок, Поступление/Списание ДС | Движение товаров, денег, цен |
| **Регистры** | Товары, Взаиморасчёты, Доходы, Расходы, Цены, Скидки | Учёт остатков и оборотов |
| **Отчёты на СКД** | Взаиморасчёты, Движение товаров, Доходы и расходы | Аналитика по контрагентам и номенклатуре |
| **Роли** | БазовыеПрава, ПолныеПрава | Разграничение доступа |
| **Параметры сеанса** | ТекущийСотрудник | Автозаполнение ответственного |
| **Функциональные опции** | ВестиРасчётЗарплаты | Управление видимостью зарплатных реквизитов |

**Ключевые решения**

**1. Проверка корректности ИНН**

Реализован алгоритм проверки контрольной суммы для:
- **Юридических лиц** — 10 цифр
- **Физических лиц** — 12 цифр

Проверка работает в двух местах:
- при **изменении поля** — подсветка ошибки и вывод текста рядом
- при **записи** — предупреждение и отказ от сохранения

**2. Автозаполнение полного наименования**

При вводе краткого наименования сокращения ОПФ разворачиваются автоматически:

- `АО "Вектор"` → `Акционерное общество "Вектор"`
- `ООО "Ромашка"` → `Общество с ограниченной ответственностью "Ромашка"`
- `ИП Иванов` → `Индивидуальный предприниматель Иванов`

Если пользователь **вручную** изменил полное наименование — оно не перезаписывается.

**3. Управление пользователями ИБ**

Из справочника **«Сотрудники»** можно создавать и редактировать пользователей информационной базы.

**Форма администратора** содержит:
- реквизиты сотрудника
- флажок `ВходРазрешён`
- поле `ИмяДляВхода`
- поле `Пароль` (режим пароля — звёздочки)
- команду **«Случайный пароль»** — генерирует 5–6 символов и показывает их

**Логика при записи:**
- если пользователь ИБ уже есть — обновляются его реквизиты
- если нет и флажок выставлен — создаётся новый с ролью `БазовыеПрава`
- при снятии флажка — отключается стандартная аутентификация

**4. Выбор формы сотрудника по правам**

В модуле менеджера справочника **«Сотрудники»** переопределено событие `ОбработкаПолученияФормы`:
- **Администратор** видит форму с управлением входом
- **Обычный пользователь** — только реквизиты сотрудника

**5. Параметр сеанса «ТекущийСотрудник»**

При входе пользователя параметр сеанса автоматически заполняется сотрудником,  
у которого `ИдентификаторПользователяИБ` совпадает с текущим пользователем ИБ.

Это используется для:
- автозаполнения поля **Ответственный** в контрагентах
- автозаполнения ответственного в документах

**6. Расчёт цен и скидок**

Общие модули **`ЦеныСервер`** и **`ЦеныВызовСервера`** содержат функции:
- `ЦенаНаДату(Номенклатура, Дата)` — срез последних цен
- `СкидкаНаДату(Номенклатура, Дата)` — скидка для номенклатуры или её группы

Используются в документах **«Установка цен»**, **«Установка скидок»**,  
**«Реализация товаров и услуг»** для автоподстановки.

**7. Проведение документов**

**Поступление товаров и услуг** формирует движения:
- по регистру **Товары** — приход
- по регистру **Расходы** — услуги
- по регистру **Взаиморасчёты** — общая сумма

**Реализация товаров и услуг** формирует движения:
- по регистру **Товары** — расход со средней себестоимостью
- по регистру **Доходы** — выручка
- по регистру **Расходы** — себестоимость
- по регистру **Взаиморасчёты** — общая сумма

При нехватке остатков — отказ от проведения с сообщением.

**8. Динамическая доступность поля КПП**

Поле **КПП** доступно только для контрагентов-юридических лиц.  
Логика отрабатывает:
- при **чтении** элемента (`ПриЧтенииНаСервере`)
- при **изменении** поля `Тип`

- **Язык 1С (BSL)** — обработчики, запросы, алгоритмы

<h3>💡 2. Дипломный проект: «Управление ИТ-фирмой» (часть 2)</h3>

Здесь описаны три новые подсистемы, расширяющие конфигурацию:

- **Учёт** — бухгалтерский учёт с планом счетов и проводками
- **Зарплата** — расчёт оклада, премий, больничных и отпусков
- **Взаимодействие** — задачи и бизнес-процессы

**Что добавлено**

| Подсистема | Объекты | Что умеет |
|---|---|---|
| **Учёт** | План счетов Управленческий, ПВХ ВидыСубконто, регистр бухгалтерии Управленческий, отчёт ОСВ | Двойная запись, субконто, оборотно-сальдовая ведомость |
| **Зарплата** | Регистр сведений Календарь, ПВР Начисления, регистр расчёта Зарплата, три документа начисления | Расчёт оклада, премий, больничных, отпусков |
| **Взаимодействие** | Справочник Роли, регистр ИсполнителиРолей, задача Задача, процесс Поручение | Адресация задач по сотрудникам и ролям |

**Ключевые решения**

**1. Бухгалтерский учёт**

Создан **план счетов Управленческий** с предопределёнными счетами:

| Счёт | Наименование | Субконто | Признак |
|---|---|---|---|
| 41 | Товары | Номенклатура | Количественный |
| 50 | ДенежныеСредства | — | — |
| 60 | РасчетыСПоставщиками | Контрагенты | — |
| 62 | РасчетыСПокупателями | Контрагенты | — |
| 70 | РасчетыССотрудниками | Сотрудники | — |
| 90.1 | Выручка | — | Пассивный |
| 90.2 | Расходы | — | Активный |

**Регистр бухгалтерии Управленческий** с корреспонденцией и ресурсами `Сумма` и `Количество`  
(количественный, небалансовый).

Документы **Поступление**, **Реализация**, **Поступление ДС**, **Списание ДС**  
доработаны для формирования проводок.

**Особенность реализации:** себестоимость при реализации рассчитывается  
по данным регистра бухгалтерии (виртуальная таблица `Остатки` на `МоментВремени()`),  
а не по регистру накопления Товары.

**2. Оборотно-сальдовая ведомость**

Отчёт на СКД по виртуальной таблице `РегистрБухгалтерии.Управленческий.ОстаткиИОбороты`.

- **Группировки:** Счет (с иерархией) → Субконто1
- **Ресурсы:** начальный остаток, обороты, конечный остаток по Дт и Кт
- **Параметры:** НачалоПериода и КонецПериода с быстрым доступом

**3. Расчёт зарплаты**

**Регистр сведений Календарь** хранит рабочие дни для расчёта нормы времени.

**План видов расчёта Начисления** с предопределёнными видами:

| Вид расчёта | Особенность |
|---|---|
| Больничный | Вытесняет ОплатуПоОкладу |
| Отпуск | Вытесняет ОплатуПоОкладу |
| ФиксированнаяПремия | — |
| ОплатаПоОкладу | Вытесняется Больничным и Отпуском |
| ПремияПроцентом | Базовая — ОплатаПоОкладу |

**Регистр расчёта Зарплата** с периодичностью «Месяц»,  
графиком из регистра Календарь.

Три документа начисления:

- **НачислениеСписком** — фиксированные суммы
- **НачислениеОплатыПоОкладу** — пропорционально отработанным дням
- **НачислениеПремииПроцентом** — процент от базы

Все документы формируют парные проводки:
- Дт 90.2 Расходы — Кт 70 РасчетыССотрудниками (субконто Сотрудник)

**4. Взаимодействие (задачи и процессы)**

Реализована работа с задачами:

- **Справочник Роли** — для адресации задач группе сотрудников
- **Регистр сведений ИсполнителиРолей** — связь ролей и сотрудников
- **Задача** — с адресацией по регистру, текущий исполнитель = `ТекущийСотрудник`
- **Процесс Поручение** — точка старта, действия и завершения

**Обработчик `ПриСозданииЗадач`** дозаполняет задачи реквизитами процесса.
**Форма ЗадачиМне** — динамический список по виртуальной таблице `Задача.Задача.ЗадачиПоИсполнителю` с командой **«ПринятьКИсполнению»**.  
Пользователь видит задачи, адресованные ему лично и через роли.

**Технологии**

Дополнительно к базовому проекту использованы:

- **Бухгалтерский учёт** — план счетов, регистр бухгалтерии, субконто, корреспонденция
- **Расчёт зарплаты** — планы видов расчёта, регистры расчёта, вытеснение, базовый период
- **Бизнес-процессы и задачи** — адресация, роли, динамические списки
- **СКД** — отчёт «Оборотно-сальдовая ведомость»
